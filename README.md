# Obsidian Predictor (мод)

Мод на Fabric для Minecraft 26.3. До того как world eater зальёт периметр водой, он показывает, где вода дойдёт до
лавы и образует обсидиан. Кроме того, он показывает взрывоустойчивые блоки, которые TNT world eater не снесёт:
обсидиан, waterlogged-блоки и так далее.

> Логика предсказания взята из [EQUENOS-2/Obsidian-Predictor](https://github.com/EQUENOS-2/Obsidian-Predictor)
> (`obi_predict.py`, автор EQUENOS). В этом репозитории она перенесена на Java (мод) и на Rust
> ([отдельная утилита](rust/README.md)) без изменений алгоритма.

По сути это та же утилита, только внутри игры. Не нужно делать litematic, вводить координаты Corner 1 и копировать
файл вейпоинтов. Метки появляются прямо в мире и сами обновляются, когда меняются блоки.

- **Красные метки** — лава, которую нужно закрыть или осушить. Метка на поверхности лавового озера значит: закрыть
  поверхностные источники в радиусе как минимум 20 блоков.
- **Фиолетовые метки** — группы взрывоустойчивых блоков, по одной метке на связную группу. При экспорте в Xaero они
  чёрные, как в оригинальной утилите.

## Установка

Jar скачивается в [Releases](https://github.com/Domen-1/ObsidianPredictorMod/releases).

| Куда | Что |
|---|---|
| Клиент | этот jar + Fabric API |
| Сервер (по желанию) | этот jar + Fabric API. Даёт общие предсказания, которые читают незагруженные чанки с диска |

Без мода на сервере у всех остаётся локальный режим.

## Как пользоваться

Нажмите **O** (переназначается в «Управление → Obsidian Predictor») или введите `/obsidian`:

1. Задайте два угла периметра: в полях или кнопкой **Here**, встав в угол.
2. Запустите:
   - **Start here** — расчёт на вашем клиенте по загруженным чанкам. Недостающие чанки подсвечены жёлтым, их нужно
     облететь. Расчёт начнётся, когда соберутся все.
   - **Start on server** — сервер прочитает всю область с диска, ничего грузить не нужно, и поделится результатом.
     Остальные открывают **Server jobs...** и нажимают **Follow**.
3. Метки обновляются сами. Перекрыли лавовое озеро блоками — через пару секунд его метка пропадёт. Пока world eater
   непрерывно меняет блоки, метки пересчитываются не реже раза в 10 с.
4. **Export Xaero waypoints** записывает `.minecraft/obsidianpredictor/<имя> waypoints.txt`. Формат и порядок
   строк те же, что у оригинальной утилиты.

В углу экрана видно: прогресс, сколько меток, а также расстояние и направление до ближайших красной и фиолетовой.

### Команды (клиент)

| Команда | |
|---|---|
| `/obsidian` | открыть окно |
| `/obsidian pos1 [x y z]`, `/obsidian pos2 [x y z]` | задать угол (по умолчанию — где вы стоите) |
| `/obsidian area <from> <to>` | задать оба угла |
| `/obsidian start` | локальный расчёт |
| `/obsidian start server [имя]` | общий расчёт на сервере |
| `/obsidian jobs`, `/obsidian join <id>` | список задач сервера / следить за задачей |
| `/obsidian stop`, `/obsidian clear` | остановить (метки остаются) / убрать и метки |
| `/obsidian kill <id>` | остановить задачу на сервере (владелец или оператор) |
| `/obsidian export` | файл вейпоинтов Xaero |

### Команды (сервер, операторы и консоль)

| Команда | |
|---|---|
| `/obsidianpredictor list` | задачи: прогресс, число меток, память |
| `/obsidianpredictor start <имя> <from> <to>` | запустить задачу из консоли |
| `/obsidianpredictor stop <id>` | остановить задачу |
| `/obsidianpredictor waypoints <id>` | записать вейпоинты задачи в `<мир>/obsidianpredictor/` |
| `/obsidianpredictor export <from> <to> <имя>` | сохранить загруженные блоки в `.litematic`, например для отдельной утилиты |

### Настройки сервера

`config/obsidianpredictor-server.json`:

| Ключ | По умолчанию | |
|---|---|---|
| `maxChunksPerJob` | 6400 | наибольшая область на задачу (1280×1280 блоков) |
| `maxJobs` | 4 | задач одновременно |
| `chunkReadsPerTick` | 8 | сколько чтений чанков начинать за тик на задачу (8 = 160 чанков/с) |
| `maxPendingReads` | 32 | одновременных чтений чанков на задачу |
| `opsOnly` | false | запускать задачи могут только операторы |
| `liveUpdateSeconds` | 10 | пока блоки меняются, пересчитывать не реже этого (0 — только когда изменения прекратятся) |
| `idleStopMinutes` | 60 | останавливать задачи, за которыми никто не следит столько минут (0 — никогда) |

## Нагрузка на сервер

Главный поток не загружает чанки ради задачи. Уже загруженные чанки копируются, это микросекунды на секцию. Остальные
читаются через стандартное хранилище чанков, с преобразованием формата для чанков старых версий, и разбираются в одном
фоновом потоке с низким приоритетом. Там же идёт и сам расчёт.

Замер на реальном мире: 4096 чанков (1024×1024, вся высота, около 400 млн блоков), выделенный сервер без игроков.

| | |
|---|---|
| время | 26 с на чтение чанков (упирается в настройку 160 чанков/с) + 1,6 с расчёт |
| код мода в главном потоке | 5–60 мкс за тик |
| средний тик | 0,7–0,8 мс во время задачи, как и в простое |
| память | от нескольких МБ до нескольких сотен МБ на задачу, зависит от местности (видно в `/obsidianpredictor list`) |

## Точность

Ядро — построчный перенос `obi_predict.py` (через Rust-версию). Где Python берёт элемент из `set`, мод использует
порядок добавления. Поэтому блок группы или лавовой зоны, на котором стоит метка, может отличаться от Python-утилиты
на несколько блоков. Найденные лавовые зоны и группы взрывоустойчивых блоков совпадают полностью.

Что проверено:
- **Юнит-тесты** (`./gradlew test`). Эталонный вывод Python для двух схематик из `src/test/resources/predictor` должен
  совпасть точно: и при чтении прямо из litematic, и через снимок мира, как в игре.
- **Реальные миры.** На мире 26.3 и на чанках, сохранённых в 1.21.4, результат серверной задачи побайтово совпал с
  отдельными утилитами на Rust и Python, запущенными на `/obsidianpredictor export` той же области. Проверены чтение
  с диска, загруженные чанки и 30+ обновлений вживую, пока текла вода.
- **Клиентский gametest** (`./gradlew runClientGameTest`, открывает окно игры). Выделенный сервер с построенным
  бассейном из воды, лавы и обсидиана. Проверяется, что локальный расчёт равен серверному, живые обновления у обоих,
  экспорт в Xaero, команды и окна. Скриншоты — в `build/run/clientGameTest/screenshots`.

## Отдельная утилита (Rust)

В [`rust/`](rust/README.md) лежит консольная версия со старым сценарием: на входе litematic, на выходе файл
вейпоинтов Xaero. Пригодится там, где мод поставить нельзя. Она в несколько сот раз быстрее Python-оригинала.

## Сборка

```sh
JAVA_HOME=/путь/к/jdk-25 ./gradlew build     # jar мода в build/libs
cd rust && cargo build --release             # утилита в rust/target/release
```
